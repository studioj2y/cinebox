# CINEBOX 移植为微信小程序的可行性分析

- 日期：2026-09-16
- 分析人：Buddy
- 分析对象：`movie-mood`（CINEBOX）当前工作树
- 结论口径：**技术可行性**（代码能不能搬）与**落地可行性**（能不能过审、值不值得）分开评估

---

## 0. 一句话结论

**技术上可移植，但不是"搬"而是"重写"——UI 与视觉层约 6 成要重做；真正的决定因素不是代码，而是四道合规闸门：域名备案、主体类型、AI 生成内容、影视类目。**

在这四道门的成本被接受之前，不建议开工。若已有**企业主体 + 一个已备案域名**，最优解是先用 `web-view` 套壳（0.5–1 人天）验证小程序入口是否真有增量，再决定要不要投入原生重写。

## 1. 现状盘点（移植对象的真实体量）

| 模块 | 文件 | 体积 | 内容 |
| --- | --- | --- | --- |
| 页面结构 | `index.html` | 9.4 KB | 三屏（wall / quiz / result）+ 全局视觉层 |
| 样式 | `css/style.css` | 29.1 KB | 令牌、四行海报墙、过场 keyframes、两处断点 |
| 交互 | `js/app.js` | 31.6 KB | 分层抽样出题、过场时间线、幽灵层、打字机、深链、海报生成 |
| 推荐引擎 | `js/match.js` | 12.4 KB | 纯函数、零 DOM 依赖 |
| 影片数据 | `data/movies.js` | 272.3 KB | **540 部** |
| 影片简介 | `data/overviews.js` | 244.8 KB | **522 条** |
| 题库 | `data/questions.js` | 79.0 KB | **137 题 / 358 选项 / 14 类** |
| 海报图 | `images/posters/*.webp` | **19.9 MB** | **540 张**，均 37.8 KB（最大 78 KB / 最小 6.2 KB） |
| 海报合成依赖 | `js/html2canvas.min.js` | 194.0 KB | 仅"生成分享海报"用 |
| 后端 | `api/interpret.js` + `api/_lib/core.js` | 16 KB | Vercel Serverless，代理 AI + 限流 + 白名单 |

**包体核算（关键）**

| 项 | 原始 | gzip |
| --- | --- | --- |
| 首屏必需代码（不含 html2canvas） | 678.6 KB | **201.8 KB** |
| 海报图（540 张） | 19.9 MB | — |

- 微信小程序限制：**单个分包/主包 ≤ 2 MB，所有分包合计 ≤ 30 MB**（服务商代开发 ≤ 20 MB）。
- 结论：**代码体量完全不是问题**（678 KB ≪ 2 MB，gzip 后仅 202 KB）；**真正的包体问题是图片**——540 张海报 19.9 MB，塞进任何单个分包都不可能，必须外链 CDN / 云存储。而外链又撞上闸门 1（域名白名单）。

## 2. 分模块可行性 × 工作量

| # | 模块 | Web 现状 | 小程序实现 | 可行性 | 工作量 |
| --- | --- | --- | --- | --- | --- |
| 1 | 首屏海报墙 | 4 行 `animation: translateX(-50%)` 无限滚动 | `view` + CSS animation 同样可行 | 高 | 0.5–1 天 |
| 2 | 全局视觉层 | 极光 `mix-blend-mode:screen` + `blur(90px)`；颗粒 `mix-blend-mode:overlay`；暗角 | `mix-blend-mode` 在小程序渲染层不可靠 → 预渲染位图或 canvas 合成 | **中** | 1–2 天 |
| 3 | 答题屏骨架 | `position:sticky` 顶栏、卡片、进度条 | Skyline 下不支持 sticky → 改 fixed + 占位；`overflow:auto` → `scroll-view` | 高 | 0.5 天 |
| 4 | 过场四阶段 | `transition` + `setTimeout` 时间线（520/950/260/800/320ms）+ `quizLocked` 防穿透 | CSS transition 受支持，逻辑可 1:1 搬 | **高** | 0.5 天 |
| 5 | 回复幽灵层 | `view` + `animation` | 同 | 高 | 0.5 天 |
| 6 | 选项错落淡入 | `animation-delay` 阶梯 | 同 | 高 | 0.2 天 |
| 7 | 毛玻璃 | `backdrop-filter: blur()` | 受限/不稳 → 纯色 `rgba` 兜底 | 高 | 0.2 天 |
| 8 | 结果页错落入场 | 9 项 `fadeUp` 阶梯 | 同 | 高 | 0.5 天 |
| 9 | **分享海报生成** | `html2canvas` 抓 DOM（194 KB） | **原生 canvas 2D + `canvasToTempFilePath` + `saveImageToPhotosAlbum`** | **中高** | 2–3 天 |
| 10 | AI 解读 | `fetch('/api/interpret')` | `wx.request` + 云函数/云托管（key 必须留在服务端） | 高 | 1–2 天 |
| 11 | 打字机 | `setInterval` 逐字 | 同 | 高 | 0.2 天 |
| 12 | 分享 / 深链 | `?m=<id>` + OG meta | `onShareAppMessage` / `onShareTimeline`（path 带 movieId；`imageUrl` 做卡片图） | 高 | 0.5 天 |
| 13 | 二维码长按识别 | `<img>` | `image` + `show-menu-by-longpress` | 高 | 0.1 天 |
| 14 | 推荐引擎 | 纯函数、零 DOM | **可直接复用** | 高 | 0.2 天 |
| 15 | 数据层 | 全局 `window.MOVIES` 等 | 改模块化，或按需从云端拉 | 高 | 0.5 天 |

**合计约 10–16 人天**（纯开发，不含合规等待与审核往返）。

值得注意：**引擎与数据层几乎零成本**（`match.js` 12 KB、题库 79 KB、影片 272 KB 直接可用）；成本集中在**视觉特效重做**与**海报生成重写**这两块——恰好也是这个产品最值钱的两块。

## 3. 四道合规闸门（决定性，非技术）

### 闸门 1 — 域名 ICP 备案（最硬的一道）

- 小程序所有网络请求走 `wx.request`，**网络图片**（`<image>` 组件）底层走 `wx.downloadFile`，两者都必须在后台配置"服务器域名"白名单。
- 白名单域名必须是 **HTTPS + 已完成 ICP 备案**。
- **现状冲突**：`cinebox.studioj2y.icu` 部署在 Vercel（海外节点），**海外主机无法完成 ICP 备案**。
- 影响面：AI 接口（必经）+ 540 张海报（19.9 MB 进不了包，只能外链）。
- 代价：买国内域名（¥30–100/年）+ 备案（免费，约 1–2 周）+ 把 API 与静态资源迁到国内可备案主机（腾讯云轻量 / 阿里云 / 微信云托管）。

> 另外：微信自 2023-09 起要求**小程序本身也需 ICP 备案**（个人主体同样需要），这是独立于域名备案的第二道手续。

### 闸门 2 — 主体类型

| 能力 | 个人主体 | 企业主体 |
| --- | --- | --- |
| 原生小程序 | ✅ | ✅ |
| **`web-view` 内嵌网页（套壳方案）** | ❌ **不支持** | ✅（需配置业务域名，域名需备案） |
| 微信支付 | ❌ | ✅ |
| 获取手机号 | ❌ | ✅ |
| 深度合成 / AI 生成内容类目 | 通常无法过审 | 需资质 |

**这条直接决定了"最省事的套壳路线"能不能走**：个人主体后台连"业务域名"入口都没有。

### 闸门 3 — AI 生成内容（本项目专属高风险）

- 核心卖点「✦ 不良有话说」是**生成式 AI 文本**。
- 个人主体 + AI 生成内容普遍过不了审；面向公众提供生成式 AI 服务还涉及《生成式人工智能服务管理暂行办法》的备案/安全评估要求。
- 影响：可能需要**砍掉或弱化**这个功能——而它是产品差异化的主要来源。

### 闸门 4 — 影视类目与素材版权

- 官方《小程序备案服务内容选择指引》中，`文娱 > 其他视频 / 视频广场 / 微短剧`、`休闲娱乐 > 院线影城、演出` 对**个人备案均为"不建议选择"**，单位主体需《信息网络传播视听节目许可证》等前置资质。
- 本产品不播放视频，形态是"图文推荐 + 评分"，理论上可归入 `文娱 > 行业资讯` 或 `工具`，但**需与审核预沟通**，存在被判"类目不符"的风险。
- 更实际的版权面：540 张电影海报 + 影片简介 + TMDB/豆瓣/IMDb 评分。在 H5 上，域名自主、无平台审核；在小程序生态里，这类素材来源**更容易被追问**。

## 4. 三条路线对比

| 路线 | 做法 | 前置条件 | 工作量 | 优点 | 致命点 |
| --- | --- | --- | --- | --- | --- |
| **A. 原生重写** | WXML/WXSS/JS 重做 UI，复用引擎与数据 | 备案域名 + 主体 | 10–16 人天 | 体验最佳；可一键存相册；分享卡片原生 | 成本最高；AI 与类目审核风险叠加 |
| **B. `web-view` 套壳** | 小程序内嵌现有 H5，零重写 | **企业主体** + 已备案业务域名 | 0.5–1 人天 | 功能 100% 保留；后续迭代仍在 H5 侧 | 个人主体完全不可用；且"纯网页容器"型小程序本身有被审核判"功能过于简单"的风险（需实测） |
| **C. uni-app / Taro 双端** | 一套代码编译 H5 + 小程序 | 备案域名 | 8–14 人天 | 后续两端同步 | 现有手写 CSS/动画要重构才能编译通过，收益不明确 |
| **D. 不做，维持 H5** | —— | 无 | 0 | 无审核、无备案门槛、改完即上线；微信内可直接打开链接（OG 卡片已优化） | 没有小程序入口 / 留存 / 相册保存 |

## 5. 视觉降级清单（做之前先接受的心理预期）

| Web 特性 | 小程序可用性 | 替代方案 |
| --- | --- | --- |
| `mix-blend-mode: screen / overlay`（极光、颗粒） | 不可靠 / 不支持 | 预渲染位图 + 透明度动画，或 canvas 合成 |
| `backdrop-filter: blur()`（顶栏、卡片毛玻璃） | 受限 | 纯色 `rgba` 底 |
| `position: sticky`（答题顶栏） | Skyline 不支持 | `fixed` + 占位元素，或 `sticky-header` 组件 |
| 通配选择器 `*` | WXSS 不支持 | 显式列出元素类型 |
| `filter: blur(90px)` 大半径 | 性能风险高 | 降半径或用位图 |
| 鼠标跟随辉光 | 无鼠标 | 删除 |
| `html2canvas` DOM 级截图 | 不可用 | 原生 canvas 逐层重绘 |
| 微信内长按保存网页图 | 体验差 | **小程序更好**：`saveImageToPhotosAlbum` 直接存相册 |

## 6. 小程序到底多给了什么（收益侧）

**给**：搜索/扫码/附近入口；原生分享卡片（可带缩略图）；一键保存到相册；订阅消息召回；"我的记录"留存；流量主广告（需认证 + UV 500）。

**不给 / 反而更差**：必须备案、必须审核、AI 与影视内容受限、包体与域名约束、以及 H5 那套"改完就上线"的迭代自由度。

**判断**：本产品是典型的**一次性测试型**工具（答 5 题 → 看一部片 → 大概率不回来）。小程序最大的增量价值恰恰是**留存与召回**，而这里几乎用不上；它最大的成本（备案 + 审核 + 视觉重做）却要**全额支付**。投入产出比不佳。

## 7. 如果要做：建议里程碑

| 阶段 | 内容 | 备注 |
| --- | --- | --- |
| **M0 合规前置** | 域名 + 备案 + 小程序备案 + 主体选择 + 类目预沟通 | **不可跳过，1–2 周，且可能直接否决项目** |
| M1 服务端迁移 | AI 接口与静态资源迁到可备案主机；海报上 CDN | 同时解决闸门 1 |
| M2 引擎与数据层 | `match.js` 直接搬；`data/*` 改模块化 | 成本最低，先做 |
| M3 UI 重写 | 首屏 → 答题 → 结果；先保功能、后补视觉 | 建议先砍特效 |
| M4 能力替换 | canvas 海报、`wx.request`、分享、相册权限 | 海报生成是最大单点 |
| M5 视觉回补 | 极光 / 颗粒 / 毛玻璃按小程序能力重新实现 | 按 §5 降级清单逐项处理 |

---

## 8. 最终建议

1. **若为个人主体**：不建议做原生移植。闸门 1 / 3 / 4 三条同时压在头上，AI 功能大概率要砍，投入 10+ 人天后可能仍上不了线。
2. **若已有企业主体 + 一个已备案域名**：优先走 **B 路线（`web-view` 套壳）**，0.5–1 人天，现有产品 100% 保留。先验证"小程序入口是否真带来增量用户"，再决定是否投入 M3–M5 的重写。
3. **若两者都没有**：**维持 H5**。在公众号 / 聊天里贴链接已可用，分享卡片（OG）也已优化过。把精力投在内容与传播上，性价比远高于为了"有个小程序"而做一次重写。如果确实想要小程序入口，**先去办备案**——这一步决定后面所有事。

## 附：本分析的事实依据

- 包体/体积数据：本机实测（`du`、`ls`、`node` 读取源文件并 gzip）
- 分包限制（主包/分包 ≤ 2 MB，合计 ≤ 30 MB）：微信小程序官方《分包加载》文档
- `<image>` 网络图片需 `downloadFile` 合法域名 + 域名需 ICP 备案：微信官方《域名管理》
- `web-view` 个人主体不支持、业务域名需备案：微信官方《业务域名》+ 开放社区答复
- WXSS 不支持 `position: sticky` / `mix-blend-mode` / 通配选择器：微信官方 Skyline WXSS 支持列表
- 各类目对个人备案的开放情况：《小程序备案服务内容选择指引》
- 个人主体能力限制（支付/手机号/web-view）：微信开放社区与备案指引汇总
- 小程序 ICP 备案（2023-09 起）：微信官方备案要求
- 海报生成需 `canvasToTempFilePath` + 网络图先经 `wx.getImageInfo` + `saveImageToPhotosAlbum` 授权：微信官方 Canvas API 文档

> 注：平台规则会变，落地前请以微信官方最新文档与审核答复为准。
